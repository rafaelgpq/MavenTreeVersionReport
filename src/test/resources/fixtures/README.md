## Fixtures

### `maven-generated/` (genuine Maven output)

Generated by `fixtures/generate-fixtures.ps1` from the synthetic projects in `fixtures/libs` and
`fixtures/projects` (all `org.example` namespaces). Tool versions used are in
`maven-generated/tool-versions.txt` (Apache Maven 3.9.16, Temurin JDK 21.0.12.1, maven-dependency-plugin 3.11.0).

Per case (`conflict`, `noconflict`, `classifier`, `managed`, `multimodule`):

- `<case>.tree.txt`: plugin `outputFile` (plain tree, no log prefixes, `appendOutput=true` for the reactor).
- `<case>.console.log`: redirected console output (`[INFO] ` prefixes, reactor banners and module headers).

Exact plugin invocation (per module, run from the fixture project directory):

```
mvn -B -ntp org.apache.maven.plugins:maven-dependency-plugin:3.11.0:tree -Dverbose=true -Dtokens=standard -DoutputType=text -DappendOutput=true -DoutputFile=<file>
```

The libraries are installed into an isolated local repository (`target/fixture-work/m2`), so the user's repository is
untouched. Profiles/settings: none beyond Maven defaults (the generator passes `-B -ntp`, no `-P`).
The first run needs network access to Maven Central to download the plugin; normal unit tests need neither Maven nor
network.

Expected results are asserted in `FixtureEndToEndTest`:

| Case | Expectation |
|---|---|
| conflict | `org.example.lib:shared:jar` under lib-a (1.0), lib-b (2.0, omitted for conflict with 1.0), lib-c (1.0, test, omitted for duplicate), lib-d > lib-e (3.0, omitted for conflict): one conflict |
| noconflict | `shared` 1.0 under lib-a and (omitted duplicate) lib-c: shared child, no conflict |
| classifier | `shared:jar:native` 1.0 vs 2.0 under lib-g / lib-h is a conflict; plain jar and test-jar are separate identities |
| managed | `shared` 2.0 under both parents, `version managed from` is provenance only |
| multimodule | mod-one shared only, mod-two nothing, mod-three conflict, multi-parent root-only |

### `hand-authored/` (NOT Maven output)

Hand-written inputs for diagnostics Maven would never produce (malformed markers, orphan hierarchy). They are not
generated fixtures. `malformed.console.log` is expected to fail strict analysis (exit 1: `IMPOSSIBLE_HIERARCHY`,
`MALFORMED_TREE_LINE`) and to be INCOMPLETE in lenient mode (exit 2). The teaching trees under the repository's
`examples/` directory are likewise hand-authored.

Raw fixture files stay unannotated on purpose: extra comment lines would change the data being parsed. Console logs
differ between regenerations (timings and paths), tree files are reproducible byte for byte.

Regenerate generated fixtures only when intentionally changing them:
`powershell -ExecutionPolicy Bypass -File fixtures\generate-fixtures.ps1 -Maven <path-to-mvn.cmd>`.
